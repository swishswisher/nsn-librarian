# Library question answering (Phase 3B)

Ask the Librarian is a retrieval-first view over the existing Phase 3A search index. It does not scan the filesystem, build a separate index, or save a conversation. The authenticated API route selects readable, connected roots before searching. The server rechecks current scan and source permissions before it constructs a context of at most eight sources. A newer in-progress scan makes the answer partial while the last completed snapshot remains searchable.

Sources are one verified excerpt (at most 240 characters) per file, file metadata, or an active human-approved Memory description (at most 400 characters) with complete authorized provenance. Repeated checksum copies do not corroborate each other. The context may also contain bounded relationship explanations and structured version-order facts for those selected sources. Notebook narrative is not used because the current Notebook records do not establish a complete per-root authorization boundary.

One OpenAI Responses request receives the question (at most 500 characters), source title, connected-root display name, relative path, trust/current state, one bounded excerpt or metadata label per source, optional source character range, selected relationships (explanation at most 240 characters), and version facts. This is still private Library information sent externally. No original full text, raw media, absolute local path, internal physical-file identity, or database ID is sent as a source identifier. The response uses `store: false`, a maximum of 700 output tokens, and `OPENAI_QA_MODEL` when set (otherwise the existing OpenAI model configuration). The shared SDK wrapper can retry twice, so one question can cause up to three HTTP attempts. No recursive search or tool loop is available to the model.

The model returns up to six claims, each with source IDs. The server rejects unknown citations, unsupported numeric/version statements, weak lexical support, and purported multi-source synthesis without independent sources. This validation reduces unsupported claims but is not a proof of semantic truth or a substitute for human review. Sources and uncertainty remain visible. Question, source context, answer text, and prompt are not stored by this feature. `LibraryAnswerUsage` stores only status, model, token counts when available, HTTP-attempt count, source count, processing version, error category, and timestamp. The current answer exists only in the page state until replaced or the page is closed.

The API is behind the human session boundary and returns no-store responses. Model failure leaves ordinary Library search available and does not synthesize a fallback answer. No Bridge command, filesystem operation, recommendation decision, Memory approval, or Notebook update is triggered by asking a question.

**Deployment privacy decision:** Phase 1 already introduced bounded persisted source excerpts. Phase 3B additionally sends selected authorized excerpts, Memory descriptions, and related metadata to OpenAI when Deanne asks a question. Review and approve that external transmission and excerpt-retention policy before deployment; implementation alone is not privacy approval.
