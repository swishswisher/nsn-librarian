# NSN Librarian system architecture

Engineering map for the baseline `6a1a4f074668038f5b556413769dd6178ca752eb` and its whole-project remediation. Read [PRODUCT_CONSTITUTION.md](PRODUCT_CONSTITUTION.md) first. The machine suggests. Deanne decides. Nothing moves without approval.

This map complements the existing Bridge, Search, answering, Mind and Knowledge design documents; it does not replace their feature contracts. [SYSTEM_INVARIANTS.md](SYSTEM_INVARIANTS.md) defines mandatory consistency rules, [CHANGE_IMPACT.md](CHANGE_IMPACT.md) identifies sibling paths, and [STRUCTURAL_DERIVED_STATE_AUDIT.md](STRUCTURAL_DERIVED_STATE_AUDIT.md) records confirmed violations and remediation status. A described invariant is a required contract, not evidence that the audited baseline already satisfied it. Open findings are explicit in the register.

## Boundaries and ownership

The installed Electron Bridge and its loopback compatibility service own physical files, native folder selection, local root grants and filesystem checks. The application owns authenticated review history, proposals, approved plan snapshots, derived Knowledge/Search/Memory and signed command coordination. The AI provider receives only the material authorized for a specific operation and produces proposals. Neither a database row nor an AI response authorizes a physical move.

There are two approved human identities in this installation, authenticated by allowlisted Google subject/email and signed session cookies. The database has no per-user root ownership column. Human administration is installation-wide; optional permitted-root restrictions on Search/Ask remain additional restrictions. Device authentication is distinct: Ed25519 request signatures bind method, pathname, body, device, timestamp and a one-use persisted nonce. Pairing redemption proves possession of a short-lived one-use pairing code. Public release manifests disclose release metadata only.

Canonical current readable root means enabled, read granted, CONNECTED, no disconnect/hide/merge timestamp and no canonical redirect. The Prisma, SQL and in-memory definitions live in `src/lib/bridge/current-readable-root.ts`. A device command additionally requires the same connected library, device and native root, and an eligible paired device. Physical execution/Undo additionally requires explicit action permissions, approved immutable actions and verified physical identity. Historical navigation and cessation/revocation commands deliberately have different purposes; see the exceptions in the invariants document.

## Subsystem map

Memory has an independent serverless consumer: production Vercel Cron issues authenticated GET `/api/cron/memory-recovery`. `memory-recovery.ts` selects existing pending review generations and calls the canonical transactional builder. A 20-owner/45-second work budget, 15-second owner transactions, per-owner advisory locks, exact generation checks, durable UTC retry backoff and aggregate health make overlap, failure and process death recoverable. Migration 36 adds only retry/health state; migration 35 is unchanged. Page callbacks accelerate work; they do not supply autonomous liveness. Memory renders pending/inspection counts and last-success information. The configured daily schedule is supported even on Hobby, but production activation, runtime and protection reachability remain separate operational gates. See [MEMORY_RECOVERY_OPERATIONS.md](MEMORY_RECOVERY_OPERATIONS.md).

## Derived-state graph and lock boundaries

Physical full scan + verified reads → provisional observations → human authority → eligible Memory and effective typed Knowledge → current Search → bounded Ask sources/claims. Reviewed organization decisions → versioned approved preferences → new proposals → human plan approval → explicit execution → verified action journal/report → execution history → explicit Undo. Notebook and curated graph are human/history interfaces; their narrative is not an alternative source of current Search/Ask truth.

Current publication takes the transaction-scoped `scan-publication:<rootId>` advisory lock, then the root share lock, then loads/checks current authority and writes one derived stage with its completion marker. Contention returns incomplete for bounded retry. Different roots progress independently. PostgreSQL backend death releases transaction locks.

Human authority locks/version-CAS precede reading prior authority. Event, materialized state, source invalidation and durable derived-work admission commit together. Provider/extraction/full inventory I/O is outside database transactions. Local physical execution deliberately holds root/run authority through one bounded action and its outcome publication; the durable native journal repairs a lost database commit. Memory reconstruction is Serializable and locks required observations before parent/source mutations. New overlapping authority locks use stable order or return a retryable conflict on database serialization/deadlock.

Physical operations cannot be atomically committed with PostgreSQL. They therefore need a local durable journal admitted before work, exclusive non-overwriting filesystem effects and replay-safe result application. A report outbox alone covers only the period after an operation returns. Unknown outcomes require explicit reconciliation and preserved action history, never automatic repeated movement or invented success.

Migration cannot manufacture missing physical proof from older deployments. A nonterminal local owner without its captured authority revision remains unresolved if no bound journal proves its outcome. Ordinary retry retains the pending history and performs no new action; resolving such pre-journal uncertainty requires human inspection rather than inferring success/failure from a pathname.

Physical generation is a database ordering protocol; server/native clocks are diagnostic, not proof that discovery followed a move. Completed history is preserved. Current Knowledge/Memory and current Search fail closed during unresolved physical work or until a matching inventory exists; explicit historical Search still applies root authorization. A new complete snapshot can satisfy an older reconciliation obligation only when newer than its owned scan, in the current physical generation and connection revision.

Lock scopes are independent per owner/root. Fingerprint reconciliation uses the same identity advisory lock for native sync and connection repair, then sorted root locks. Native identity ownership outranks a stale duplicate's apparent activity; cross-device collisions reject. Curated graph merges use exclusive graph coordination while ordinary curation/cleanup shares that coordination and locks the affected object. PostgreSQL transaction locks release on backend death; native journals retain filesystem proof beyond it. The accepted external-process path-component race is recorded as REC-003, not advertised as an OS-level atomic containment guarantee.

## Privacy boundary

Original files, unrestricted absolute paths, media and filesystem authority remain local. Native scans send selected-root metadata, safe location labels, relative paths and checksums. Authorized temporary reads send bounded extracted text/technical media data to the application for the requested analysis; native report outboxes can hold raw temporary replies locally until delivery. The application strips raw read reports before cloud command-result persistence. It may persist approved product metadata, observations, decisions, derived bounded excerpts/previews, source ranges, provenance manifests, usage counts, recommendations, plans and execution history. Such excerpts are still private data; they are not a replacement raw library.

The existing Bridge media policy and [LIBRARY_ANSWERING_ARCHITECTURE.md](LIBRARY_ANSWERING_ARCHITECTURE.md) define provider transmission. Ask sends the question ≤500 characters, ≤8 authorized selected sources, one verified excerpt ≤240 characters/file or Memory description ≤400, bounded relationship/version facts, safe relative-path metadata and trust/current state; no full raw text, raw media, absolute paths or internal source IDs. The provider response has `store: false`, bounded output and at most two SDK retries. Observation/media analysis has its own explicit grant and existing bounded input contract. No agent task grants privacy/deployment approval merely by implementing code. Ordinary validation uses synthetic files, mocked AI, unset OPENAI_API_KEY and localhost disposable databases only.

Authentication/root denial fails closed for new reads and evidence eligibility while preserving audit history. Review/history pages can show prior authorized decisions to the authenticated human; this does not make their material current evidence. Privacy restrictions must also hold on retries, error responses, logs and pending result storage.
